# Words for Chenle

The fifth map entry (`eyes`) opens a single-paper composer. Visitors choose one of six paper designs, five ink colours and up to eight stickers. Submissions require 1–60 Unicode code points after trimming. Name is optional (24 characters). There is no composing-language selector: the shared `lib/note-design.mjs` utility detects Chinese/Korean/English from the text, and the server applies it independently.

The existing D1 database now stores real submissions in `chenle_notes`; the existing fan-wishes table and API are unchanged. New records are always immediately approved/public, regardless of client-supplied status. `GET /api/notes` returns only approved records. `GET /api/notes/mine` returns the current anonymous visitor's own records, based on an HTTP-only random cookie and a server-side hash. Actor/network identifiers are never returned. Existing local-only notes remain available under My Notes and are never uploaded automatically. Public notes, personal notes and moderation queues are visibly separated. When the public board is empty, designed examples are clearly labelled.

After submission, the visitor enters the board, sees a publication confirmation, and earns the module star. Reading a card also earns the star once. The first screen contains no wall of sample cards. Each wall page has up to ten cards.

The owner signs in through the small Management login link (`/signin-with-chatgpt?return_to=%2F%23eyes`). The management tab appears only after `/api/notes/access` confirms an authenticated email matching the runtime secret `NOTE_MODERATOR_EMAIL`. Authorization for list/review and every approve/reject action is enforced server-side using dispatch-owned identity headers. Do not expose this secret to the browser. Change it in Sites settings if site ownership changes.

Translation: every message reader has a target selector (Chinese/Korean/English) and a Translate link. This opens Google Translate with automatic source-language detection in a new tab. It is a real external translation view, not an inline translation or a local dictionary. No translation API key is configured. Translation is visitor-initiated; note text is not automatically sent to a translation provider. Inline machine translation would require configuring a server-side provider separately.

Local save compatibility helpers remain in `lib/chenle-messages.ts` for the previous 20–80-character records. They are not used to submit new notes. The active API independently validates the new 1–60-character limit and design allowlists. `worker/notes.mjs` contains the shared-board endpoints; the deterministic build combines it with the pure design utilities and original Worker into one ESM entrypoint. No third-party backend credentials are required.

Schema migration: `drizzle/0001_chenle_notes.sql`. Publication applies it; no table is created during requests. Rate limits: 5 notes per visitor/day, 30 per shared network/day. These are abuse limits rather than verified human identity. New notes do not require pre-approval. Owner-only hiding remains available after publication.

Checks: `npm run test:notes`, `npm run test:fan`, `npm run check`, `npm run build`. Test coverage includes real SQL migrations, automatic detection, Unicode limits, style/colour/sticker validation, owner authorization, author privacy, pending exclusion, publication/rejection, translation links and compose-first rendering. Browser QA is unavailable in this environment.

The board now renders a dreamcore night sky: each message is a native keyboard-accessible star button, opening the existing personalized paper reader. Ten separated positions are used per sky page, with sender and status labels so examples/private/moderation notes stay distinguishable. Ambient meteors use six Chenle-related vector heads (basketball, microphone, dolphin, headphones, music, puppy) with light trails. They do not intercept pointer events. A still-sky toggle and prefers-reduced-motion both disable meteors. The dark theme is scoped to board mode; the compose-first paper editor stays unchanged. `test:notes` includes constellation layout and markup checks.

Sticker studio: 23 existing character/camera/team images are allowlisted in `NOTE_STICKER_CATALOG`. Each new placement stores `{uid,id,x,y,size,rotation}` in the existing JSON sticker column: normalized position and width percentages, with bounded size and angle. No schema migration is needed. The server preserves backward compatibility with legacy emoji stickers while the new picker uses actual image assets. Pointer capture handles dragging and two-pointer pinch/rotation; size/angle sliders and arrow/Delete keys provide alternatives. The reader restores the saved layout with the same art assets and six designed stationery backgrounds.

Header Fan Wishes now links directly to this shared board. The legacy `fans` hash is retained as a board alias rendered by the same guestbook component; no separate fan-wish page is mounted. The map entry opens the composer. Composition now uses a Chenle photographic scrapbook background and a sculpted title wordmark. Only blank/whitespace-only input is disallowed; one-character notes are valid, and the 60-character maximum remains enforced server-side.

Current visual direction uses a single full-page portrait collage poster with the reference composition (large portrait, tabletop and plate with miniature photo standees, upper-right and lower-left snapshots, lower-right star), covering the entire composer shell without a fading lower half. The title is now neutral pearl/ivory/silver, with no hot pink lettering. Privacy reminders remain visible. Existing historical pending records are not automatically exposed; the owner can publish them through management if desired.
